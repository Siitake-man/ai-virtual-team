# スキル：セッション開始準備 (session-start)

このスキルは、新しい開発セッションを開始する際にAIが自動的かつ自律的に実行する一連の準備・同期手順です。前回の文脈を迅速に復元し、スムーズに作業に入ることを目的とします。

## プロジェクト固有の設定値（ai-virtual-team）

| 変数 | 設定値 |
|:---|:---|
| `TaskFile` | `docs/task.md` |
| `PlanFile` | `docs/implementation_plan.md` |
| `SpecsDir` | `docs/` |
| `LearningMemoDir` | `docs/learning-memos/` |
| `HandoverDir` | `docs/handover/` |
| `AppServer` | `run.ps1`（FastAPI port:8000 + Streamlit port:8501 並行起動） |
| `主要技術スタック` | Python 3.13 / FastAPI / Streamlit / google-genai SDK v2.x / Pydantic v2 / JSON永続化 |

---

## 実行フロー

AIは本スキルを検知またはユーザーから指示された場合、以下のステップを**すべて自律的に一括で実行**します。

### ステップ1：最新コンテキストの自動スキャンと同期

AIはプロジェクト内の以下のファイルを順番に読み込み、現在のプロジェクト状況を完全に復元します。

1. **`docs/task.md`**: 直近のタスク進捗状況と完了状態の把握
2. **`docs/implementation_plan.md`**: 設計図の変更履歴の確認
3. **`SPEC.md`** と **`GEMINI.md`**: 仕様と開発制約の再確認
4. **`docs/learning-memos/` 内の最新の `学習メモ_YYYYMMDD.md`**: 前回の詳細な振り返りと直近の課題
5. **`docs/handover/` 内の最新の `jules_handover_YYYYMMDD.md`**（存在する場合）: Julesの成果の把握

### ステップ2：Julesの成果確認と同期（非同期リレーの受け取り）

Julesが裏で進めていた作業（PR作成やリファクタリング）を確認します。

1. **コミット・差分の確認**: 最近のコミットログから、Julesの変更内容を把握する（コマンドはユーザーに提示して実行を促す）
2. **Julesの引き継ぎメモの読み込み**:
   - `docs/handover/jules_handover_YYYYMMDD.md`（存在する場合）を読み込み、完了したタスクと残課題を把握する
   - `docs/learning-memos/学習メモ_Jules_YYYYMMDD.md` を確認し、導入された新しい技術や構成変更を理解する
3. **用済みファイルの自動アーカイブ**:
   - 前回の指示書 `docs/handover/prompt_for_jules_YYYYMMDD.md` が存在し、対応するJules成果ファイルが確認できる場合、これを `docs/handover/archive/` フォルダへ退避させる

### ステップ3：環境の健全性チェック

現在の作業ディレクトリや設定を確認します。

1. **プロジェクトルートの確認**: `c:/Users/bonob/Project/ai-virtual-team/` が正しいルートであることを確認
2. **`.env` の整合性チェック**:
   - `.env` ファイルが存在するか確認
   - `GEMINI_API_KEY` が設定済みか（値は表示しない）確認
   - `API_BASE_URL=http://localhost:8000` が設定済みか確認
3. **`data/projects/` の状態確認**: JSONファイルが正常に存在するか確認

> ⚠️ **起動コマンド（`run.ps1`）の自動実行は行いません。** 必要であればユーザーへ提示する。

### ステップ4：5分マイクロタスクの特定

今日の最初の「小さな勝利（Small Win）」を定義します。

- `docs/task.md` の「次の5分タスク」セクションと、Julesの成果から残ったタスクを統合し、最も早く（5分以内）完了できる作業を**1つだけ**特定します。
- 特定の基準:
  1. **動作確認系**: APIキーを設定して実際に動かす確認作業（最優先）
  2. **小さな実装**: 既存コードへの数行の追加
  3. **ドキュメント更新**: タスクリストや仕様書の修正

### ステップ5：ユーザーへのセッション再開宣言

すべての準備が完了した後、AIはユーザーに以下のフォーマットで報告し、合意を得て最初のタスクに着手します。

```markdown
### 🌅 セッション再開準備完了

前回の文脈およびJulesの作業成果（あれば）を同期・復元しました。

**【プロジェクト: AI Virtual Team Builder】**
- **現在のフェーズ**: Phase X / Step Y
- **前回完了**: ○○
- **Julesによる変更**: ○○（なければ「なし」）
- **現在の未解決課題**: ○○

**【.envステータス】**
- GEMINI_API_KEY: ✅ 設定済み / ⚠️ 未設定
- API_BASE_URL: ✅ 設定済み / ⚠️ 未設定

**【今日の最初のアクション（5分タスク）】**
- [ ] ○○ (例: run.ps1 を起動して動作確認)

アプリを起動する場合は以下のコマンドをターミナルで実行してください:
`.\run.ps1`

それらの確認から作業を開始してよろしいでしょうか？
```

---

## 留意事項

- `run.ps1`（FastAPIサーバー + Streamlitの同時起動）は自動で行わず、ユーザーに起動コマンドを提案・確認すること
- `git pull` などのGitコマンドも自動実行しないこと
- 不要になった指示書のアーカイブ処理は、誤操作によるデータ消失を防ぐために慎重に判定すること
- `.env` ファイルの中身（APIキーの値）を絶対にチャットに出力しないこと
