# スキル：セッション終了振り返り (session-wrap-up)

このスキルは、開発セッションを終了する際にAIが自動的かつ自律的に実行する一連の振り返り・同期手順です。ユーザーの可処分時間を最大化し、「再開時にゼロから思い出す時間」を完全に排除することを目的とします。

## プロジェクト固有の設定値（ai-virtual-team）

| 変数 | 設定値 |
|:---|:---|
| `TaskFile` | `docs/task.md` |
| `PlanFile` | `docs/implementation_plan.md` |
| `SpecsDir` | `docs/` |
| `LearningMemoDir` | `docs/learning-memos/` |
| `HandoverDir` | `docs/handover/` |
| `AppServer` | `run.ps1` (FastAPI + Streamlit 並行起動) |
| `主要技術スタック` | Python / FastAPI / Streamlit / google-genai / Pydantic / JSON |

---

## 実行フロー

AIは本スキルを検知またはユーザーから指示された場合、追加の対話による時間浪費を避けるため、以下のステップを**すべて自律的に一括で実行**します。

### ステップ1：セッションファクトの構築（脳内整理）

AIはまず、本セッションで実行した以下の情報を整理します。

- `CompletedTasks`: 完了したタスクの一覧（`docs/task.md` のステータスを参照）
- `Troubles`: 遭遇したエラー、原因、対策の3点セット
- `ModifiedFiles`: 作成・修正したファイルとそれぞれのシステム上の役割
- `SpecsModified`: 変更した仕様や影響のある仕様書（`SPEC.md`, `GEMINI.md` 等）
- `JulesTasks`: Jules（夜間エージェント）に委ねるべきタスク（Phase 2以降のCSS装飾・リファクタリング等）
- `NextAction`: 次回再開時に迷わず5分で着手できる超具体的なファーストアクション

### ステップ2：既存ドキュメントの自動更新

AIは以下のドキュメントを読み込み、自律的に書き換えます。

1. **`docs/task.md` の更新**:
   - 完了したタスクのステータスを `✅ 完了` に変更する
   - 「次の5分タスク」セクションを最新の状態に書き換える
   - 更新日を最新の日付に変更する

2. **`docs/implementation_plan.md` の更新**:
   - アーキテクチャやデータフローに変更があった場合、設計図を更新する
   - 更新履歴テーブル（存在しない場合は末尾に追加）に日付と変更内容を追記する

3. **`SPEC.md` の確認**:
   - 実装で仕様から外れた箇所があれば、理由とともに備考として追記する

### ステップ3：不要スペックの自動アーカイブ（Specsクリーンアップ）

AIは `docs/` フォルダ内をスキャンし、以下の基準でファイルの整理を判断します。

- **基準**: 最新のルールやドキュメントと内容が重複・矛盾している、またはすでに廃止された古い仕様を含むファイル
- **アクション**: 該当するファイルを削除するのではなく、`docs/archive/` フォルダ（存在しない場合は自動作成）に移動させる

> ⚠️ 破壊的変更を防ぐため、アーカイブ候補はユーザーに確認してから移動すること

### ステップ4：学習メモの自動生成

AIは以下のパスに、詳細な学習メモを新規作成します。

- **保存先**: `docs/learning-memos/学習メモ_YYYYMMDD.md`
- **内容要件**:
  - NotebookLMへの連携を想定し、情報量は極力多く・ファクトベースで詳細に記述
  - PM視点での **Why / What / Where** の観点を必ず含める
  - 専門用語は「身近な例えでの理解」引用ブロックで補足する
  - 今日のトラブルシューティング記録を含める
  - 次回セッションに向けた「次のアクション」を末尾に記載する

### ステップ5：Julesへの引き継ぎ指示書の自動生成

AIは以下のパスに、夜間エージェントJules向けの指示書を作成します。

- **保存先**: `docs/handover/prompt_for_jules_YYYYMMDD.md`
- **内容要件**:
  - Julesが作業中に迷わないよう、具体的なファイルパスを明記する
  - `requirements.txt` のインストール方法（`.venv/Scripts/activate` → `pip install -r requirements.txt`）を明記する
  - 主要な技術スタック（FastAPI / Streamlit / google-genai SDK v2.x / Pydantic v2）の制約を記述する
  - コーディング規約（日本語コメント・型注釈必須・`any`禁止）を含める
  - Jules向けの具体的なタスクを優先順位付きリストで記述する
  - **Julesに実行させないこと**: `run.ps1` の自動起動、APIキーの書き換え、データファイル（`data/projects/`）の削除

### ステップ6：ユーザーへの最終出力（3大打返し）

ドキュメントの書き換えと生成がすべて完了した後、AIはユーザーに以下の内容を最終出力として提示します。

1. **【今日やったこと＆詰まったポイント】** サマリーと、事象・原因・対策の3点セット。アーカイブに移動したファイルの一覧。

2. **【Git一括コマンド】** ユーザーがコピー＆ペーストするだけでコミットとプッシュが完了する一括コマンド（PowerShell形式）:
   ```powershell
   cd C:\Users\bonob\Project\ai-virtual-team
   git add -A
   git commit -m "【セッション終了】YYYY-MM-DD: <本日の主な変更内容>"
   git push origin main
   ```

3. **【Jules Web UI用指示プロンプト】** ユーザーがJulesのセッション起動UIにそのままコピペして送信できる短いテキスト。

4. **【次回再開時の魔法のプロンプト】** ユーザーが次回チャットを開いた際に、最初の入力としてコピペするだけで文脈とJulesの成果を同期するための引き継ぎプロンプト。

---

## 留意事項

- `git` コマンドや `npm` / `uvicorn` / `streamlit` コマンドの自動実行は行わず、必ずステップ6でユーザーに提示して実行を促すこと
- 最新情報との同期やファイルのクリーンアップは、ファイルの破壊的変更を防ぐために慎重に判定すること
- `data/projects/` 以下のJSONファイルは絶対に削除・移動しないこと（ユーザーのプロジェクトデータのため）
- `.env` ファイルはGitの管理外であることを必ず確認し、コミットコマンドに含めないこと
